# learning about wysiwyg editors, finding 2 great working examples

What I have learned is that the exeCcommand is a key.  
Most of the formatting is done through that, through those commands.

It is deprecated, but not because it doesn't work, but because not any browser supports it.  
So, given that I only care about Firefox (in other words, I'd never use a Microsoft or Google Browser), 
this is not a problem. Also, wysiwyg editing is typically for a CMS, meaning, the users are members of a group / commiity,  
and can be expected to use a decent browser.

More precisely, I'm making it for myself and a small number of people.  
The fact that we can only use Firefox is totally cool about us.  

But this learning also was a revelation as I realized that those days when I was using Wind' and TinyMCE are 
basically not over, as it's the same old javascript technology with the same old execcommand "tool".

JQuery can only spice up the old methods.  
In short, the WYSIWYG editor is an anciant technology.  
Which today, in the "readonly" era with touch screens, is far less used than say, before 2010.

Also, the difference between this or that editor can't be very-very significant... 

## the two new findings


1. [RichText by webfashionist](https://github.com/webfashionist/RichText/tree/master)

This looks very similar to JQTE.  
It is, however, more sophisticated ... or rather: absolutely sophisticated...
Talking code-wise...

I was very close to just dropping this "diy" (aka dimys) project,  
but RichText has a few little "bugs"... 

But, either way, it has an implementation of the wonderful 
"defaultParagraphSeparator" command, which decides whether a **div or a p tag** is the default when the user enters some text.

Before I found this in webfashionit's code, I was seriously confused not understanding how everyone decides to use div instead of p? 
Now I know, and websfashionist incorporated an elegant choice: 
we can decide how we like our editor :) 

His code is very good. To 99% it's just what I want :) 


2. [Rich Text Editor by dasdebjeet](https://github.com/dasdebjeet/rich_text_editor) 
also known as **Easy rich text editor**. see https://www.jqueryscript.net/text/easy-rich-text-editor.html

Now, this is interesting.  
Instead of the 3000 lines, this runs up to 150 lines of jquery code.  
And works perfectly...  

I just saw an enhancement request at one of the editors' github page, that the bold button should be active if the selected has the bold attribute... 

Sure, Libreoffice works like that... But what do we want exactly?  
A big application or something to work with?  
I mean, a good tool doesn't have to be big and all bells and whistles, and what not.  
These decorations, I suspect, take up the bulk of the 2700 extra lines compared to the 150... by dasdebjeet.
